# HireRight — Amazon S3 resume storage

Private resume **files** live in S3. Profile **text** (parsed resume, skills, onboarding) lives in **Neon PostgreSQL** (`profiles.data`).

## Architecture

| Data | Where |
|------|--------|
| Resume PDF/DOCX bytes | **S3** (private bucket) |
| `resumeText`, wizard fields | **Neon** + browser localStorage |
| File metadata | **`stored_files`** table (Neon) + `profiles.data` (`resumeStoragePath`, `resumeFileId`, `storageProvider`) |

**Stack:** React (Vite) → Node API → S3 + Neon. No AWS keys in the frontend (`VITE_*` must never include AWS secrets).

## Environment (repo-root `.env` only)

Required for S3:

```env
AWS_REGION=us-east-1
S3_BUCKET=your-bucket-name
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
```

Recommended with Neon-only auth:

```env
VITE_AUTH_PROVIDER=api
DISABLE_SUPABASE=true
DATABASE_URL=postgresql://...neon...
```

Optional:

- `S3_PRESIGN_EXPIRES_SECONDS` — presigned download TTL (default `900`)
- `AWS_DEFAULT_REGION` — fallback if `AWS_REGION` unset

After changing `.env`, restart the API (`npm run dev:all` or `npm run dev:backend`).

## IAM policy (app user)

Grant on **your resume bucket only** (replace `BUCKET`):

- `s3:PutObject`, `s3:GetObject`, `s3:HeadObject`, `s3:DeleteObject` on `arn:aws:s3:::BUCKET/*`
- `s3:ListBucket` on `arn:aws:s3:::BUCKET` with prefix `resumes/` (optional but helps CLI/smoke tests)

Bucket: **Block all public access** ON. Objects are never public URLs.

## Object key layout

```
s3://{S3_BUCKET}/resumes/{safe_email}/{uuid}.pdf
s3://{S3_BUCKET}/resumes/{safe_email}/{uuid}.docx
```

- `{safe_email}` — lowercased email; `@` and other chars → `_` (e.g. `user_gmail.com`)
- Files appear under the **`resumes/`** prefix — not at the bucket root

## API

| Method | Path | Auth | Behavior |
|--------|------|------|----------|
| POST | `/api/resume/upload` | Bearer token | Validates PDF/DOCX, max **2 MB**, uploads to S3, updates Neon profile |
| GET | `/api/resume/download` | Bearer token | Presigned URL redirect (or `?format=json`) |

Upload body:

```json
{
  "filename": "resume.pdf",
  "file_base64": "...",
  "contentType": "application/pdf"
}
```

Success (200):

```json
{
  "ok": true,
  "storageProvider": "s3",
  "storagePath": "resumes/user_gmail.com/uuid.pdf",
  "bucket": "your-bucket-name",
  "resumeUrl": "/api/resume/download",
  "fileId": "..."
}
```

## Frontend — when S3 is used

Only **`ResumeUpload`** (onboarding step 1 / profile) calls `/api/resume/upload`:

1. User must be **signed in** (API session / Bearer token).
2. File must be **`.pdf` or `.docx`** (≤ **2 MB** for cloud storage).
3. **`.doc`, `.txt`, `.md`** — parsed locally only; **not** uploaded to S3.

On success the UI shows **“Saved to secure storage (S3)”** and the object key.

Other screens (apply flow, interview upload, employer resume DB) parse text only unless wired to the same API.

## Verify locally

1. API startup log:

   `Object storage: Amazon S3 (bucket=..., region=...)`

2. Smoke test (lists `resumes/` and tests Put/Delete):

   ```bash
   npm run s3:test
   ```

3. End-to-end API upload:

   ```bash
   node backend/node/scripts/test-auth-workflow.mjs
   ```

   Expect: `resume upload OK s3 resumes/...`

4. App test: log in → onboarding → upload PDF ≤ 2 MB → Network `POST /api/resume/upload` → **200**, `storageProvider: "s3"`.

5. AWS Console: **same account** as the bucket → region **`AWS_REGION`** → bucket **`S3_BUCKET`** → folder **`resumes/`**.

6. Schema (once per Neon DB):

   ```bash
   npm run db:init
   ```

   Creates `stored_files`. Upload still writes to S3 if this table is missing, but download metadata may be incomplete until `db:init` runs.

## Troubleshooting

| Symptom | Likely cause |
|---------|----------------|
| Empty bucket root | Objects are under **`resumes/`** only |
| No new objects after upload | Not logged in, file > 2 MB, or not PDF/DOCX |
| `503` / storage skipped | Missing `AWS_REGION` or `S3_BUCKET` on API process |
| `AccessDenied` on PutObject | IAM policy or wrong bucket/region |
| API log OK but console empty | Wrong AWS account, wrong region, or wrong bucket name |
| Parse works, no S3 | `.doc` or session invalid — check UI error / Network tab |

## Production (Render + Vercel)

- Set the same **AWS_*** and **S3_BUCKET** on the **Render** API service (not Vercel).
- Keep **`VITE_AUTH_PROVIDER=api`** on Vercel build env.
- **`VITE_API_URL`** must point to the Render API in production.
